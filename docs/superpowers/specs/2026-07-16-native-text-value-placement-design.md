# Native Text 高价值动态选位与广告接入文档设计

## 目标

Native Text 在 AI 流式回答期间保持实时插入，同时持续评估同一关键词的全部候选位置。当后续出现明显更高价值的位置时移动链接，并在回答结束后校准到全文最高分位置。

同时新增独立广告接入指南，既可供外部媒体开发者理解通用协议，也可供本项目维护者定位实现、配置和调试链路。

## 候选范围

- 仅扫描当前 Native Text 指令所属的 AI 回答容器。
- 英文关键词匹配忽略大小写，锚点文字保留 AI 原文形式。
- 排除已有链接、`code`、`pre`、`script` 和 `style` 区域。
- 多个广告分别评分，但候选位置不能位于其他广告已经创建的链接内。

## 价值评分

### 结构分

结构分只取最高一项，不叠加：

- `h1`–`h3`：40 分。
- `strong`、`b`：30 分。
- `h4`–`h6`：25 分。
- 普通段落：10 分。

### 上下文分

- 购买、下单、价格、优惠、`buy`、`purchase`、`price`、`deal`：35 分。
- 推荐、值得、首选、`recommend`、`worth`、`best`：25 分。
- 适合、帮助、效果、`suitable`、`help`、`benefit`：20 分。
- 位于回答全文前 20%–45%：15 分。
- 候选所在句子已经出现句末标点：10 分。
- 不推荐、不适合、避免、风险、注意、`not recommend`、`avoid`、`risk`、`caution`：减 30 分。
- 引用或重复列表语境：减 15 分。

每个上下文词组类别最多计分一次。首期使用上述确定性中英文词表和 DOM 结构计算，不调用额外模型。分数相同时选择更靠前的候选位置。

## 混合移动策略

1. 收到 `inject_anchor` 后立即选择当前最高分候选并插入，保持实时反馈。
2. 流式内容更新时重新扫描。只有新候选分数至少比当前位置高 15 分时才移动，避免频繁跳动。
3. AI 回答结束后执行最终校准，忽略 15 分移动阈值，选择全文最高分候选。
4. 移动时先把旧锚点还原成原始文本，再在新位置创建相同 `anchor_dom_id` 的锚点。

## 跳转与监测

- 锚点 `href` 始终使用 `landing_url`。
- 点击时后台请求 `click_tracking_url`。
- 移动后重新绑定曝光观察器。
- 曝光继续按 `anchor_dom_id` 在单次会话中去重；已完成曝光的广告移动后不重复上报。

## 代码边界

- `lib/ads/dom.ts`：候选收集、结构与上下文评分、旧锚点还原、动态选位和移动。
- `app/components/ads/use-native-text-anchors.ts`：根据流式/完成状态调用选位逻辑并管理曝光观察器。
- `app/components/chat/message-assistant.tsx`：向 Native Text Hook 传递当前回答状态。
- `lib/ads/dom.test.ts`：验证评分、移动、最终校准和原文保留。

## 独立广告接入指南

新增 `docs/advertising-integration-guide.md`，包含：

1. 广告数据来源与整体数据流，明确唯一广告平台为 `http://10.1.51.76:8080`。
2. Small Card 通用 HTTPS 协议、鉴权、请求响应、渲染、跳转和监测规范。
3. Native Text WebSocket 协议、流式 Chunk、锚点指令、动态高价值选位和监测规范。
4. 本项目的文件映射、环境变量、广告位 ID 与 Key、代理边界和 CSP 配置。
5. 本地验证、关键词测试、无匹配与连接失败排查。

文档必须明确：Small Card 当前经过本项目 `/api/ads/small-card` 传输代理，但广告匹配与素材均来自 `10.1.51.76:8080`；Native Text 由浏览器直接连接同一广告平台。

## 验证范围

- 标题候选优先于普通段落。
- 加粗候选优先于普通段落。
- 流式阶段只有分差至少 15 分才移动。
- 回答结束后无阈值地校准到最高分候选。
- 移动后保留原文大小写、落地页跳转和点击上报。
- 已完成曝光的锚点不会因移动重复曝光。
- 完整 TypeScript 类型检查和项目测试通过。
